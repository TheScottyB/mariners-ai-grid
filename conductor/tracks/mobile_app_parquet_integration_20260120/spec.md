# Track Specification: Mobile App Parquet Integration

## 1. Goal
To update the Mariner's AI Grid mobile application to natively support reading and visualizing **Parquet** weather seeds. This enables the use of the "Cloud Slicer's" most efficient output format, delivering "Extreme Data Efficiency" to the end user.

## 2. Context
The "Cloud Slicer" optimization track has successfully implemented Parquet export, achieving superior compression compared to Protobuf. However, the current mobile app (`SeedManager.ts`) relies on `apache-arrow`'s `tableFromIPC` method, which is incompatible with standard Parquet files. We need to bridge this gap to complete the end-to-end pipeline.

## 3. Requirements

### Functional Requirements
*   **Parquet Ingestion:** The `SeedManager` must be able to load and parse `.parquet` files generated by the Python backend.
*   **Data Extraction:** Accurately extract weather variables (Wind, Pressure, Waves) from the Parquet table into the app's internal `SeedTimestep` format.
*   **De-Quantization:** If the Parquet data is quantized (integer values + scale/offset), the app must correctly de-quantize it to floating-point values for visualization.
*   **Performance:** Parsing a 2MB Parquet seed should take < 1 second on a modern device (iPhone 15/17 Pro).

### Non-Functional Requirements
*   **Library Selection:** Evaluate `apache-arrow` vs `parquet-wasm`.
    *   *Constraint:* If `apache-arrow` (JS) cannot read Parquet, we must use `parquet-wasm` or similar, ensuring it works within the React Native / Expo environment.
*   **Offline Capability:** The parsing must happen entirely on-device without network calls.

## 4. Out of Scope
*   Changing the Python backend to export Arrow IPC (Feather). We are sticking to Parquet as the storage standard defined in the Tech Stack.
*   Visualizing new variables (we strictly visualize what we already support).

## 5. Proposed Solution
1.  **Investigation:** Confirm if `apache-arrow` JS has *any* Parquet support or if `parquet-wasm` is required.
2.  **Implementation:**
    *   Install necessary dependencies (e.g., `parquet-wasm`).
    *   Refactor `SeedManager.ts` to use the appropriate reader for `.parquet` files.
    *   Ensure `SeedUploader` and `seed_server` support `.parquet` (already partially done, but verify).
3.  **Verification:** Load a real Parquet seed from the `demo_seeds` folder and verify data integrity on the "Chart Table".
